# Scientific execution correction v1 — 7 September 2026

The unchanged frozen scientific comparison will run on a trusted, content-checked host using the new, hash-bound scientific campaign runner. This corrects orchestration and states the narrower operational assurance explicitly; it does not assert that the historical v3/retry5 persistent-namespace or freeze-guard procedure succeeded.

## What remains unchanged

The original execution plan, acquisition and source manifests, receiver drivers, candidate configuration, normalizer, statistical scorer, routing order, baud rates, repeat policy and null-control transforms remain byte-bound to their existing identities. The schedule is 6,168 terminal units: 6,166 new executions plus two already-exposed units imported from exact retained raw/receipt evidence, never rerun. The full 30-observation cohort and the predeclared 29-observation sensitivity excluding all of observation 4491 are both scored. No observation is selected or removed based on newly observed yield.

The original per-unit bubblewrap isolation, cgroup resource limits and strict completion criteria remain in force. Input IQ is checked against its original SHA-256 before and after successful supervised execution; generated null input is content-checked, journalled and removed only after exact terminal evidence is retained. Read-only runtime contents and dependency identities are checked before execution and again before final scoring. Installed, content-checked runtime packages—not the working source tree—provide scientific package imports. The mission executable's original shebang path is made available through an explicitly disclosed read-only bind of the same component runtime.

## What is not claimed

This run trusts the host, kernel and operator. It does not claim the historical root metadata/inode attestation or a successfully frozen persistent namespace. Keeper 2072832 and the existing v3 control files are preserved without reuse as scientific execution authority. Output is written to a new UID/GID 1000, mode-0700 host directory rather than the historical private results tmpfs.

An operational amendment binding the exact runner, tests, unchanged scientific inputs and this rationale must be root-owned mode 0444 and externally RFC3161 timestamped before any new blind decoding. The runner independently checks the amendment and timestamp pair. Its default mode remains metadata-only.

## Failure and resumption policy

Malformed output and supervisor exceptions remain explicit terminal failures. Missing results, timeouts, cleanup failures, all-zero-contract failures, repeat failures and false-alarm gates retain their original meaning. A scored but incomplete campaign exits nonzero and is not described as successfully completed. Empty decoded-frame sets alone never establish success.

The exact existing operation may reuse terminal receipts and reproduce normalization without relaunching decoders. A completed generated-null ledger is reconciled against its journal before temporary cleanup. A started unit with no terminal receipt, an unjournalled null temporary, identity drift or foreign operation evidence fails closed; no such artifact may be cleared to force a rerun. No threshold tuning, receiver changes, sample reselection or yield-driven early stopping is authorized by this correction.

Progress and ETA use terminal counts and timing only. Final reporting must preserve both complete-cohort and whole-observation-exclusion scores, all failed units, null exposure and integrity checks. Completing this comparison is not by itself evidence of publication acceptance, universal superiority or deployment readiness.
