# Independent M&M clock / audio-representation review

Reviewed 2026-09-11. Scope: read-only review of `rust/mm_clock.rs`,
`examples/mm_clock_probe.rs`, and `examples/audio_representation_probe.rs`.
Only the independent test harness `examples/mm_review_tests.rs` and this report
were added by the reviewer. Historical campaigns were not modified.

## Verdict

The clock is suitable as an **experimental opt-in pre-clock soft-sample adapter**,
subject to positive/negative-control qualification and frozen implementation
identity. It is not a complete IQ demodulator and cannot yet replace the existing
progressive receiver or qualify a final scientific benchmark by itself.

No equation/sign/indexing defect was found in the public `recover` path. Its M&M
detector and omega/phase update agree structurally with the established
[GNU Radio implementation](https://raw.githubusercontent.com/gnuradio/gnuradio/main/gr-digital/lib/clock_recovery_mm_ff_impl.cc).
The interpolation is independently written linear/cubic Lagrange, not GNU Radio's
MMSE interpolator; the explicit non-bit-exact and non-novelty labels are correct.
M&M also has input amplitude/pulse-shaping assumptions, so a rate-compatible OGG
file alone is not evidence of a matched pre-clock waveform.
[GNU Radio documentation](https://www.gnuradio.org/doc/doxygen/classgr_1_1digital_1_1clock__recovery__mm__ff.html).

## Actionable findings

1. **P2 — Misleading source-preservation flag in the representation audit.**
   At `examples/audio_representation_probe.rs:70`,
   `bit_exact_float_sample_preservation` uses error against `sample * gain`.
   For float values `[-1.5, 0, 1.5]`, gain 0.5, and PCM16 values
   `[-24576, 0, 24576]`, it reports true even though the original samples changed.
   Rename that field to `bit_exact_declared_transform_preservation` and separately
   compare reconstructed PCM samples against the original float values. This is
   a result-labeling bug, not evidence of a demodulation error. It was sent to the
   owning agent; this review did not edit the owned source.

2. **P3 — Public unchecked interpolation helper.** `interpolate` accepts arbitrary
   indices and fractional arguments. Cubic index 0 and linear final index panic;
   independent tests reproduce both. `recover` maintains the needed preconditions
   and is safe for tested valid configurations, so this does not block the current
   probe. Before publishing it as a library API, make interpolation private or
   document/check its bounds and finite fractional range.

3. **Integration prerequisite — Freeze and report complete computational identity.**
   The probe result does not record its executable/source identity or full fixed
   gain/limit configuration. `wall_seconds` begins after `load_audio`, so it excludes
   conversion and ingestion. Add executable/config identity and separately named
   preparation/DSP/total timings before comparing with other programs. This is
   acceptable for an explicitly development-only probe with a surrounding frozen
   artifact manifest, not a standalone publication benchmark.

4. **Integration prerequisite — Preserve continuation semantics.** `recover` is a
   one-shot function: absolute position, omega and previous symbol are reset on each
   call. Splitting a recording into chunks is not equivalent to a full-recording
   run. A resumable streaming integration needs explicit state plus interpolation
   overlap; otherwise retain this as a separately reported whole-recording branch.

## Bounds and integrity observations

- `recover` starts position at least 1; valid steps are finite and at least 0.25;
  `position + 2 < len` ensures cubic `i-1..i+2` accesses are in range. Output is
  bounded to fewer than four times input length. No backward cursor was found.
- Nonfinite inputs/configuration and sample/error overflow fail explicitly;
  failed branches cannot become completed zero-frame branches.
- The 24 probe branches are fixed at 2 interpolators × 4 initial phases × 3 input
  gains. CRC and expected packet bytes do not enter clock decisions. Validation
  occurs after complete symbol generation, and every branch is retained.
- Full input scanning/validation is repeated per branch, and the whole recording
  plus one soft-output branch are held in RAM. This is bounded but not streaming;
  only aggregate full-pipeline measurements can establish useful speed/RAM gains.
- The source is hashed before and after; representation auditing refuses mismatched
  rates, channels and lengths rather than truncating. The gain labeling issue above
  does not change its overshoot or numerical-error calculations.
- No new theoretical algorithm or demonstrated telemetry gain follows from this
  review. Real IQ/OGG control results belong to their separate source-bound runs.

## Independent tests and numerical caveat

`work/mm-review-20260911-v1/bin/mm-review-tests-v2` passed **11/11 tests**:
5 original clock tests and 6 independent review tests. The independent tests cover
general Lagrange-basis interpolation, short integer/fractional-state M&M recurrence
for all 24 branches, 120 input lengths × 4 SPS values × 2 phases × 2 interpolators,
nonfinite configuration, determinism and invalid public interpolation calls.
The separately compiled representation suite passed **5/5 existing tests**.

An initial independent test required entire 4096-sample noise trajectories to match
within 1e-7 between an absolute-position implementation and a separately grouped
integer/fractional recurrence. One cubic branch differed by 2.8062303e-7. The final
test explicitly limits equation-equivalence assertions to the first 128 symbols
(maximum observed error 1.0978e-12) and reports long-trajectory differences rather
than pretending exact parity. All 24 compared trajectory lengths agreed. This
documents floating-point grouping sensitivity in nonlinear feedback; it is not a
GNU Radio bit-exactness claim or an excuse to change scientific acceptance metrics.

These are small correctness tests, not a sensitivity, false-positive-rate, or
reception performance benchmark.

## Independent qualification-gate review

Reviewed `examples/decoder_readiness_audit.rs`, final SHA-256
`eb76aab59f57f86edafba4cc50343838b68f294208a55d22d9242942e0b95b2f`.
The gate fails closed on changed source/artifact bytes, missing/partial completion,
bad received FCS, mismatched exact expected PDU sets, missing required positive or
negative controls, and contradictory expectations for the same source bytes.
Artifact hashes and JSON parsing operate on the same bounded read. Progressive
manifests are typed and recomputed to verify their declared session digest. The
generic IQ adapter permits only AX.25-family outer frames; it does not qualify raw
CCSDS. The M&M adapter is explicitly a 19200 Hz / 9600 baud pre-clock component
with no hidden conversion, not an end-to-end IQ receiver.

Review found and the owner fixed one additional qualification issue: the first
M&M adapter checked all 24 branch keys but ignored full loop/deframer settings.
The final adapter requires exact equality of all eight configuration fields,
explicit false packet-guided/novelty declarations, and a well-formed executable
identity declaration. Legacy results without configuration now fail qualification
with `clock_configuration_unattested`; their independently CRC-checked frame bytes
remain diagnostic evidence only. This is a meaningful restriction, not silently
upgraded legacy provenance.

The reviewer independently ran the pre-fix gate suite (30 passed, 2 ignored) and
both optional compatibility checks (2 passed). After the fix, the owning agent
reports **34 normal tests and 2 explicit compatibility checks passed**, including
eight mutated configuration fields, absent configuration, absent/true flags and
absent executable identity. Source reinspection confirms the fix is fail-closed.
The resulting four-run CANVAS5122/seeded-noise control suite passed; this establishes
only the narrow source-bound positive/negative component control, not deployment,
novelty, archive gain, or a statistically estimated false-positive rate.

Gate authenticity boundary: expected-output independence and actual execution
provenance remain owner-trusted. Declared executable identity is not cryptographic
execution attestation. The gate correctly leaves publication/deployment false.
